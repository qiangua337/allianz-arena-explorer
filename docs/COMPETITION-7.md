# 7.0 比赛流程

## 开始比赛

打开「比赛日选项 → 实战设置」，选择对手、时长、赛制和拜仁首发。好友联机时房主创建房间，朋友输入房间码，两人分别点击「本队阵容」排阵；各队 11 名不同球员，门将位置只接受门将。4 种阵型会改变场上 AI 站位，替换首发也会改变实际人物姓名、号码与球衣。

「常规赛」允许平局；「加时＋点球」在平局后踢两节加时，仍平再踢点球；「平局直接点球」跳过加时；「点球大战」直接进入五轮。3 / 6 / 10 分钟是压缩后的常规时间，两半场等长，比赛内显示 45 / 90 分钟。加时每节为常规时长的六分之一，显示到 105 / 120 分钟；死球重置不消耗比赛时间。

上半场结束后暂停，可在「阵容」调整战术与替补。单机点击继续，联机必须双方确认；换边后进攻方向与开球队交换。比分按实际进攻方向判定。

## 换人、犯规和点球

Q 和手机「换控」只切换控制球员。真正替补由「阵容」选择在场位置和未登场替补、提交调整。活球时进入待执行队列，下次边线球、角球、球门球、犯规、进球或中场执行。常规赛最多 5 人、3 次死球窗口；同一死球多人换人只占一次，中场不占窗口。加时额外增加 1 人、1 次窗口。被换下者不能再次登场，门将只能与门将互换，罚下球员不能被替补。

抢断需要身体接触且没有公平触到球才可能犯规。普通接触、鲁莽抢断、危险冲撞和累积犯规分别影响判罚；背后位置本身不直接等于犯规。黄牌累计两次变红，危险冲撞可直接红牌；罚下球员移出比赛、换控和雷达，每队少于 7 人比赛终止。禁区内判罚点球，其余直接任意球，重开时对手退让。

点球大战交替主罚，持球方方向选择落点并蓄力射门，防守方左右移动、空格或手机「扑救」选择扑救时机。每次结果来自实际球轨迹、门框与门将接触，支持提前分胜负和同轮突然死亡。双方参与人数等额，每人踢过才开始下一循环。点球记录单独显示，不加入常规进球比分。

## 手机和其他页面

阵容图使用独立屏幕排版，球员卡保持间距；候选列表可滚动，确认按钮固定在底部。手机普通比赛按攻防显示动作，点球时只显示射门或扑救。竖屏点球使用专门的球门镜头；横屏保留转播、跟随与第一人称。导航增加参观、比赛和展览入口，展览、说明、导览和联机页面统一弹窗与小屏滚动样式。打开排阵或阅读弹窗时，背景不重复绘制 3D。

6.1 的本地移动预测、服务器确认、手机 30 帧节奏修复继续保留。房间、名单与纪律细节在变化时同步，减少重复发送与复制。实际网络往返与设备帧率仍分别显示，不能用本地测试替代手机网络结果。

## 验证与范围

自动检查覆盖双方排阵、半场换边、不同球门进球归属、加时流程、点球提前获胜和突然死亡、实际换人及窗口上限、两黄变红、直接红牌与禁区点球、客户端名单同步、替换人物和罚下人物隐藏，以及原有导航、建筑、手机、物理与联网回归。

`node scripts/audit-online.mjs [网站地址]` 验证真实双连接、同源限制、移动、暂停与重连。`node scripts/audit-competition.mjs [网站地址] --full` 用公开 HTTP / WebSocket 指令跑完整两半场和点球，不注入服务器或浏览器状态；不加 `--full` 跳过等待两半场的时间。

依据 [IFAB 比赛时间](https://www.theifab.com/laws/latest/the-duration-of-the-match/)、[比赛结果与点球](https://www.theifab.com/laws/latest/determining-the-outcome-of-a-match/)、[球员与替补](https://www.theifab.com/laws/latest/the-players/) 和 [犯规与不当行为](https://www.theifab.com/laws/latest/fouls-and-misconduct/) 设计以上流程。这里仍是简化的浏览器体验赛：尚无越位、补时、VAR、完整手球及优势判罚；普通比赛中的定位球重开、门将与接触判罚也使用简化物理，不能称作完整职业足球模拟。通用球员模型并非商业足球游戏扫描模型。
