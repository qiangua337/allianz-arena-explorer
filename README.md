版本 **9.1.0：真实一脚接传、近景人物与联机画面更新**。

- 快连按传球不再把已传出的足球吸回。半自动和辅助模式可预备接球队员的一脚传球、直塞或射门，保留原方向与力度，等实际触球后才出脚；手动模式仍由玩家换控。松球附近仍可预备传射，不会在几米外直接获得球权。对照场景中，24 次快连按回吸由 24 次降为 0 次，半自动 / 辅助的实际接球后一脚再传由 0/16 变为 16/16。
- 高速低球按球与人物的实际移动路径检查接触，先碰到的队员先触球，修复擦过脚侧却被帧末位置漏掉的接球和拦截。接触半径、高球限制、护球、犯规和门将结果保留。
- 近景镜头在远离足球时继续让受控球员保持可读大小，远球通过画面边缘的方向和距离提示寻找；持球、迎球、训练和定位球保留各自取景。
- 门将使用新增的 `footballer-910` 通用模型：手套有闭合厚度、分开的手指间隙和腕带，专用腕口网格裁去腕带下露出的裸皮。外场慢速侧移与斜移调整髋部、上身回看和落脚支撑；仍共用 18 骨骼、单人物图集材质，不是球星扫描或商业游戏动作库。资源及限制见[人物资源说明](docs/PLAYER-ASSETS.md)。
- 联机对手与远端足球使用有界缓冲插值，减少快照间的停顿和回退，本机移动继续预测并接受服务器校准；暂停、中场、进球和切人会清理旧画面。改善的是远端运动的显示连续性，不会降低线路的物理 RTT，也不改变权威球权或比分。
- HUD 只写入实际变化的内容。同一真实 HUD 在 10 秒、30 Hz、300 次更新的对照中，最终模拟状态一致，DOM 属性、attribute 和 dataset 的 setter 调用合计 **9,825 → 85**；这是界面写入次数，不是实体手机 FPS，也没有降低输入或足球物理的更新频率。

本版继续保留训练、普通比赛与联机的独立流程。验证方法和测量边界见[验证记录](docs/VERIFICATION.md)。人物和场馆仍为公开资料基础上的通用或近似复原，手机尺寸检查不等同于实体手机硬件跑分。

- 六个室内区域的第三人称环绕、缩放与平移受真实房间边界约束，避免转进墙体；发布厅按台阶高度处理，包厢按实际模型顶板限高。

版本 **8.2：联机计时恢复、手机动画与短传交接**。

- 修复服务器慢回调时永久丢失比赛时间的问题，保留欠时并分步追赶；心跳可以修复失效计时器。暂停、中场和掉线时间不会补跑，恢复席位后保留半场、比分与进度。

- 固定建筑复用世界矩阵，合并重复骨架更新；手机 30 Hz 主循环下中远距离动画真正达到 20 / 12 Hz，受控球员每帧更新。模块计数减少不等于实体手机帧率保证，详见[验证记录](docs/VERIFICATION.md)。

## 本地启动

Windows 已安装 Node.js 时，双击 `启动球场.cmd`。或在本文件所在目录运行：

```sh
npm start
```

随后打开 <http://localhost:4173>。保持启动窗口开启；关闭窗口会停止本地服务。不要直接双击 `dist/index.html`：浏览器通常会限制 file:// 页面的 ES 模块。

无需安装 npm 依赖，无需编译。建议使用 Node.js 24 或更新版本，与自动检查及部署环境一致。可用 `PORT` 环境变量指定其他端口。

## 还原边界

这是公开参考资料驱动的程序化复原，并非经测量确认的施工 / BIM 模型。草坪与主要外廓以官方公布尺寸为依据，外壳气枕数量按公开统计建模。座椅数量是场景的几何数量，与官方国内赛事容量 75,024 人及实际售票清单不同。

更衣室视觉主要参考 2022 年官方照片；官方另有 2026 年 5 月更衣室整修公告，模型尚未完成整修后现状的逐处核对；球衣姓名与号码按 2026-10-20 拜仁官网一线队名单核对，更衣室和商店共用同一份数据；名册见 [docs/ROSTER.md](docs/ROSTER.md)。主客队房间的精确尺寸、连接动线、包厢陈设、商店、博物馆布展、入口和公共大厅设施的位置、楼梯尺寸及场外建筑都存在近似。第一人称按当前楼层选择可达地面；入口、环廊主要墙体和设施、楼梯侧栏有身体碰撞，未覆盖全部建筑构件。八组入口楼梯连接入口层与公共大厅，室内公共楼梯、连廊及公共大厅北侧缓坡连接其他楼层；区域导航在第一人称中只规划路线。日夜光照为实时艺术化表现。

## 检查

```sh
npm run check
```

完整检查需要 Node.js 24，部署构建通过 `.node-version` 固定主版本。测试会沿全部目的地路线采样楼面高度，并使用实际场景构建器生成的墙体、扶手和设施碰撞数据检查通路。

静态部署只需将 `dist/` 内容放到支持 HTTPS 的静态服务器。

## Cloudflare 部署

```sh
npm run check
npm run deploy
```

生产托管使用 Cloudflare Pages，项目配置见 `wrangler.jsonc`。本地探索无需 npm 依赖；
`main` 分支推送后自动检查和部署；手动部署需要已登录的 Cloudflare 账号及 Node.js 22 或更新版本。
完整操作及自行部署方法见 [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)。
